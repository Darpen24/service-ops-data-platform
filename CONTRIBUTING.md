# Contributing

Read `AGENTS.md`, `PLANS.md`, and `DECISIONS.md` before proposing work. Keep a change within one phase, use a conventional-commit message when committing, and do not add future-phase placeholders.

Before opening a pull request, run the relevant commands in `PROJECT_SETUP.md`, update documentation, describe data-model and security impact, and include rollback considerations. Never add `.env`, generated raw/processed data, credentials, or cloud connection strings.

Use small, reviewable changes. Record material choices in `DECISIONS.md` and exact failures or blocked validation in `IMPLEMENTATION_LOG.md`.
